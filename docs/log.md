## 2026-11-09
* **Creation**: [unattended-live-run](howto/unattended-live-run.md): keep a live run up with nobody at the laptop, everything on ebpf2201: a watchdog restarts a crashed receiver (two-check and port-free guard, clean-stop detection, 5 min pause in a crash loop), the NIC sampler and the pages; an hourly job starts a fresh run and deletes runs with no events, logs included. With both scripts.
* **Creation**: [2026-11-09-lb682-perlmutter-losses](results/2026-11-09-lb682-perlmutter-losses.md) (tagged `bug`): LB 682 frames (28–45 kB, ~3.7 Gbps), why the DAOS receiver isn't the sender's bottleneck, and the losses: 3 MB socket buffers, receiver crashes in E2SAR's reassembly when senders share (event number, data id), and 26–32% of clock-based event numbers never arriving.
* **Update**: the [monitor page](reference/e2sar_daos_monitor.md#the-dashboard-vizdaos_monitorservepy) no longer shows event number gaps: no gaps tile, no orange gap or yellow pending bins and no gaps column in the strip, and its Events/s ▲ marks only events the receivers lost. Perlmutter's event number counts 65.536 µs frames and ~27% of them are never sent, so gaps there aren't losses. `e2sar_daos_monitor` now ranks in DAOS and left DAOS above gap and pending in a strip bin, so a bin with any stored event shows it. Gaps stay in the JSON lines and the log line.
* **Update**: evio-interactive-view `main`: `serve.py --live` now follows the reader's `<run>_<W>.dat` bundles (and still `.evio` from older runs); `live_demo.py` and `live_replay.py` write `.dat`. [streaming-workflow](concepts/streaming-workflow.md#the-workflow) no longer notes the mismatch.
* **Fix**: the [monitor page](reference/e2sar_daos_monitor.md) no longer skips the first updates of a new run when its server restarts (a new pipeline run) while the tab stays open: it now reads the new file from its first line.
* **Update**: [e2sar_daos_monitor](reference/e2sar_daos_monitor.md) and [e2sar_daos_read](reference/e2sar_daos_read.md) handle a sender that restarts its event numbering. On LB 682 the sender restarted at 19:41 UTC from ~67.5M down to ~5.2M: the monitor's missing count froze at 1,115,247 and every new event counted as a duplicate (7.6M in 12 min), though a third of the new numbers were missing. A jump of more than `--restart-gap` (1,000,000) event numbers now starts a new segment with its own gaps (`include/e2sar_daos/event_gaps.hpp`, shared by both); late events of an older segment still fill its gaps. Restarts are reported (`restarts` in the monitor's JSON, the reader's end-of-run line). New unit suite `EventGapsTests` ([run-tests](howto/run-tests.md)).
* **Update**: Every receiver runs with a 1 GiB UDP socket buffer (`-b 1073741824`). On LB 682, receivers started by `e2sar_live_pipeline.sh` got the 3 MB default and lost ~10% of packets at the socket (`Udp.RcvbufErrors`) at ~1.5 Gbps per node. `e2sar_live_pipeline.sh`'s default `RECV_ARGS` now has it; added to the receiver commands in [ebpf-testbed](sites/ebpf-testbed.md), [e2e-no-control-plane](howto/e2e-no-control-plane.md) and [aurora-workflow](sites/aurora-workflow.md), and noted in [e2sar_daos_recv](reference/e2sar_daos_recv.md#e2sar_daos_recv), [scripts](reference/scripts.md) and [live-monitoring](howto/live-monitoring.md#waiting-for-a-sender).

## 2026-11-05
* **Update**: [e2sar_daos_read](reference/e2sar_daos_read.md#a-full-disk---min-free) survives a full disk ([#38](https://github.com/JeffersonLab/e2sar-daos/issues/38)): new `--min-free` (GiB, default 5) pauses `--live` and `--live-rm` before a file that would leave less free in `-o DIR`, and resumes once there is room. Manifest lines are written whole or not at all, and a cut-off last line is dropped on restart, so a crash no longer blocks or misdirects the restart. Tested against LB 677 run 1. [e2sar_daos_monitor](reference/e2sar_daos_monitor.md) writes its JSON lines the same way and skips lines while the disk is full. `scripts/e2sar_live_pipeline.sh` starts the reader with `--min-free 50` (`READ_ARGS`) and `status` shows a paused reader ([scripts](reference/scripts.md), [live-monitoring](howto/live-monitoring.md#waiting-for-a-sender)). New unit suite `TextFilesTests`.
* **Creation**: `scripts/e2sar_live_pipeline.sh` ([scripts](reference/scripts.md)): `start`, `stop`, `status`, `recycle` and `watch` for the live pipeline from the laptop. `recycle` replaces a run that got no events for an hour (no sender) with a new one, never touching a run with data. Documented in [live-monitoring](howto/live-monitoring.md#waiting-for-a-sender) and [streaming-workflow](concepts/streaming-workflow.md#the-workflow). `e2sar_nicmon.sh report` lists `rx_steer_missed_packets` per second only above 100 (it is mostly background multicast).
